Lesson 122: OFFSET and INDIRECT, and why the standard avoids them

Data and Lookups · Lookups · hard · Paid

OFFSET returns a cell some rows and columns away from a starting cell; INDIRECT turns a text string into a reference. You will meet both in other people’s models, so learn to read them, and learn why the standard avoids them: both recalculate on every change, so a big model crawls, and neither shows the trace arrows what it reads, so an audit goes blind. Build one of each, watch the arrow miss, break both with one row, and rewrite them. The key is OFFSET.

What you will do

  1. OFFSET(start, rows, columns) counts away from a starting cell: from Lists!B4, down as many rows as MATCH says and four columns across, lands on the site’s capacity. It is volatile, so Excel recalculates it on every change anywhere in the file. Reach capacity the long way in Summary N5:N10: =OFFSET(Lists!$B$4,MATCH(B5,Lists!$B$5:$B$10,0),4).
  2. Trace Precedents draws what a formula reads (3.6.1). On OFFSET it points at the starting cell and the code list, never at the capacity it returns, so a reviewer following arrows can’t see where the number came from. Trace N5 with Alt M P, read the arrow stop at Lists!B4 instead of a capacity, then clear it with Alt M A A.
  3. INDIRECT(text) treats a string as an address: "Lists!F" joined to a row number becomes the capacity cell. The address is text, so nothing in the file knows it points there, and it is volatile too. Reach it again in O5:O10 from a string: =INDIRECT("Lists!F"&(4+MATCH(B5,Lists!$B$5:$B$10,0))).
  4. Insert a row at the top of the list and every real reference moves with it, but OFFSET still counts from B4 and INDIRECT still builds the old address. Both return the new blank row; INDEX/MATCH in G5 follows the list. Insert a row on Lists at row 5, the top of the site list, watch N5 and O5 go wrong while G5 holds, then Ctrl+Z.
  5. Rewrite N5:N10 as INDEX/MATCH and retitle N4 Capacity (INDEX/MATCH).
  6. Clear the INDIRECT column, O4:O10, with Clear All, Alt H E A, so only the INDEX/MATCH stays.
  7. INDEX(block, 0, n) returns the whole nth column of a block, so SUM around it adds one week of the cube. It does what an OFFSET over a moving column does, and the trace arrows can see the block it reads. In J18, sum the second week of the cube without OFFSET: =SUM(INDEX($C$15:$E$20,0,2)).
  8. Does it tie? Watch Domain’s capacity on Lists move to 130 and N5 follow it, traceably.
