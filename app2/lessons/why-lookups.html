Lesson 115: Why lookups: a model reads a dataset it can’t hold

Data and Lookups · Lookups · medium · Paid

The question log is the buyers’ diligence questions, numbered, with an owner and a status, and every answer points at a cell. The first asks the Deluxe price, and the answer in F5 is a typed 15: the day the price list changes, it is wrong and nobody knows. A lookup finds the row for D in the package list on Lists and brings back its price, so the answer moves when the list does. Watch a typed answer and a looked-up one part ways, then make the log read the list. The key is VLOOKUP.

What you will do

  1. On Lists, select the Deluxe retail price in the package list, D15.
  2. VLOOKUP(key, table, column, FALSE) looks down the table’s first column for the key and returns the column you count to: "D" in Lists!$B$14:$E$16, column 3, is the Deluxe retail price. FALSE asks for an exact match, and the anchors keep the table still wherever the formula goes. Back on Q&A, enter =VLOOKUP("D",Lists!$B$14:$E$16,3,FALSE) in G5, beside the typed answer.
  3. Change the Deluxe price on Lists to 16 and watch G5 read 16 while the typed F5 still reads 15.
  4. Press Ctrl+Z to put the Deluxe price back to 15.
  5. An answer in the log is a reference to a cell that reads the data, never a typed figure, because a buyer will change the data and expect the answer to move. The lookup reads another sheet, so it is green like every link. Retype the answer in F5 as the same lookup and color it green, a link to another sheet.
  6. Clear the working lookup in G5 with Delete, so the log holds one answer.
  7. Does it tie? Watch the Deluxe price on Lists move to 17 and the answer in F5 follow it.
