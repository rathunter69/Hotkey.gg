Lesson 144: Two-way data table: ticket × member share

Data and Lookups · Scenarios and sensitivity · hard · Paid

The two-way table moves two inputs at once, tickets across and member shares down with EBITDA in the grid: the table a buyer photographs. The corner holds the output, and the row and column input cells are the two inputs it drives. Calculation set to Automatic except for Data Tables keeps a big model fast, with F9 to bring the tables up to date. Build it and mark the cells where the downside lives. The key is Alt A W T.

What you will do

  1. A two-way table moves two inputs: one set of values across the top, another down the left, and the output formula in the corner where they meet. Both edges are typed, never linked to the inputs the table drives. Start the table at C32: the corner =C24, then the tickets 12 to 16 across D32:H32.
  2. Type the member shares down C33:C37: 40, 45, 50, 55 and 60, which the percent format reads as 40% to 60%.
  3. Select C32:H37, press Alt, A, W, T, set the Row input cell to G6 and the Column input cell to G7, and press Enter.
  4. Mark the base case, $14 and 50%, in bold: F35.
  5. Turn red every cell below the live EBITDA: on D33:H37, a formula rule =D33<$C$24 with the light red fill.
  6. A Data Table reruns the model once for every cell, so a big model with tables slows down. Automatic except for Data Tables (Alt, M, X, E) recalculates everything else at once and leaves the tables until you press F9. Set calculation to Automatic except for Data Tables, then make Base washes a day, D5, 230: EBITDA moves and the grid holds.
  7. Press F9 to bring the grid up to date, put 250 back in D5, and set calculation back to Automatic: Alt, M, X, A.
  8. Does it tie? Watch Base sites at year end, D8, go from 44 to 40: every cell of D33:H37 falls and more of it turns red.
