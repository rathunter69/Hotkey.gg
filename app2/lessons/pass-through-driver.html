Lesson 146: When data tables fail: the pass-through driver

Data and Lookups · Scenarios and sensitivity · hard · Paid

A Data Table can only move an input on its own sheet, and a big model keeps its inputs on Inputs. The fix is a pass-through driver: a blank cell on the table’s sheet and, beside it, the cell the model reads, =IF(C13="",Inputs!$C$15,C13). The table drives the blank cell; when no table is running, the input passes straight through. Move the ticket to Inputs, build the driver and rebuild both tables on it. The key is IF.

What you will do

  1. Move the ticket to Inputs: type it in Inputs!C15, 14, one blended ticket for every case.
  2. Point the case tickets on Scenarios at it: C6:E6 =Inputs!$C$15 with Ctrl+Enter, then color them green as links.
  3. A Data Table can only write into a cell on its own sheet, so it cannot reach Inputs!C15. The pass-through gives it one: C13 stays blank, and C14 passes the input through until a table writes into C13. Leave C13 blank and give the model its ticket in C14: =IF(C13="",Inputs!$C$15,C13).
  4. Point the model at C14: revenue in C18 =C17*C14, and contribution per wash in C42 reading C14 in place of G6.
  5. Rebuild the one-way table on the driver: select C28:H29, Alt, A, W, T, Row input cell C13.
  6. Rebuild the two-way table too: select C32:H37, Row input cell C13, Column input cell G7.
  7. Does it tie? Watch the ticket on Inputs go from $14 to $15: EBITDA rises and both tables follow it.
