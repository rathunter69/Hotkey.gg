Lesson 121: Multi-criteria lookups: a key column, a two-condition MATCH, SUMIFS as a lookup

Data and lookups · Lookups · hard · Paid

Sponsor B wants the washes for one site on one day, and no single column of the export holds that key. Three ways, in the order the standard prefers: a key column that joins the two with & so a normal INDEX/MATCH works; SUMIFS as a lookup, when the answer is a number and the pair is unique; and the two-condition MATCH, which needs no helper column. Build all three on the export and read when each is the right one. The key is &.

What you will do

  1. A key column joins the two conditions into one string, AUS-SLA|2026-09-19, so a single MATCH can find the row. TEXT writes the date one fixed way (3.4.1), because a date on its own joins as its serial number. On Export, fill the key column J5:J94 with =B5&"|"&TEXT(A5,"yyyy-mm-dd"), site and date in one string.
  2. On Summary, build the same key in C43 from the site in C41 and the date in C42.
  3. Washes by the key column in C44: INDEX on Export’s washes, MATCH on the key in Export!$J$5:$J$94.
  4. When the answer is a number and only one row can match, SUMIFS on the two conditions adds up exactly that row, so it works as a lookup with no helper column. If the pair could repeat, it would add them together without a word. Washes by SUMIFS in C45, on the site and the date: the pair is unique, so the sum is the one row.
  5. Each comparison over the export returns a column of TRUE and FALSE, and multiplying the two makes 1 only where both hold, so MATCH(1, …, 0) finds the row with no key column. Best practice: a key column when the lookup returns text or must be audited by eye, SUMIFS when it returns a number, and the array MATCH when you can’t add a column, noted beside it as an array. In J20, find it with no key column: =INDEX(Export!$E$5:$E$94,MATCH(1,(sites=C41)*(dates=C42),0)).
  6. Does it tie? Watch the date in C42 move to Sep 20 and all three answers move together.
